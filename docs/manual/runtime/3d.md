# 3D graphics

Instance can draw in 3D: walls and floors, blocks and cylinders, textured models,
with a camera, fog and lighting. 3D is purely a way of *drawing* — the game itself
stays 2D. Instances still have an `x` and `y`, move in the room's plane, and collide
using their 2D masks. A typical 3D game is a 2D game seen from a camera standing in
the room.

Both renderers (OpenGL and the software renderer) support 3D.

## Switching 3D on

```gml
// Create event of a controller object
d3d_start();
d3d_set_hidden(true);        // hide surfaces behind others (on by default)
d3d_set_lighting(false);
d3d_set_culling(false);
```

[`d3d_start()`](../reference/3d-graphics.md#d3d_start) switches 3D mode on: it turns on
the depth buffer, so nearer things hide farther ones, and a perspective camera.
[`d3d_end()`](../reference/3d-graphics.md#d3d_end) goes back to 2D. Settings such as
fog, lighting and culling are remembered between the two.

In 3D mode:

- Everything drawn with the ordinary 2D functions — sprites, text, shapes — is drawn
  flat in the plane `z = depth` of the instance being drawn. A larger depth is farther
  away from the default camera and looks smaller; depth 0 appears at its normal size.
  [`d3d_set_depth()`](../reference/3d-graphics.md#d3d_set_depth) changes the z for the
  drawing that follows.
- The default camera looks at the room (or view) from straight in front, at a distance
  equal to the view's width. In this view the vertical axis is flipped compared to 2D:
  the room's top-left corner appears at the bottom-left.
- Room backgrounds and tiles don't line up properly under perspective; draw the
  scenery yourself instead.
- `mouse_x` and `mouse_y` are not translated through the 3D camera.

## The camera

The projection is reset to the default at the start of every frame (and every view),
so set the camera in a Draw event — usually of a camera object with a high depth, so
it draws before the rest.

```gml
// Draw event of obj_camera (depth 10000): first-person view from the player
var px, py, dir;
px = obj_player.x;
py = obj_player.y;
dir = obj_player.direction;
d3d_set_projection(px, py, 10,
    px + cos(degtorad(dir)), py - sin(degtorad(dir)), 10,
    0, 0, 1);
```

- [`d3d_set_projection(xfrom, yfrom, zfrom, xto, yto, zto, xup, yup, zup)`](../reference/3d-graphics.md#d3d_set_projection)
  places the camera at the *from* point, looking at the *to* point; the *up* vector says
  which way is up (usually `0, 0, 1`). The field of view is 45 degrees.
- [`d3d_set_projection_ext()`](../reference/3d-graphics.md#d3d_set_projection_ext) adds the
  field of view, aspect ratio and the near and far clipping distances.
- [`d3d_set_projection_ortho(x, y, w, h, angle)`](../reference/3d-graphics.md#d3d_set_projection_ortho)
  switches to a flat 2D-style projection — the way to draw a HUD on top of a 3D scene
  (turn off hidden-surface removal with `d3d_set_hidden(false)` while you do).
- [`d3d_set_projection_perspective()`](../reference/3d-graphics.md#d3d_set_projection_perspective)
  gives the default kind of perspective for an area of the room.

The camera position only affects what you see. To move the player, move the instance
as in any 2D game.

## Shapes

| Function | Draws |
|---|---|
| [`d3d_draw_block()`](../reference/3d-graphics.md#d3d_draw_block) | a box between two corners |
| [`d3d_draw_cylinder()`](../reference/3d-graphics.md#d3d_draw_cylinder) | an upright cylinder in a box, optionally closed |
| [`d3d_draw_cone()`](../reference/3d-graphics.md#d3d_draw_cone) | a cone in a box |
| [`d3d_draw_ellipsoid()`](../reference/3d-graphics.md#d3d_draw_ellipsoid) | a ball in a box |
| [`d3d_draw_wall()`](../reference/3d-graphics.md#d3d_draw_wall) | a vertical rectangle between two points |
| [`d3d_draw_floor()`](../reference/3d-graphics.md#d3d_draw_floor) | a horizontal (or sloped) rectangle |

Each takes a texture id and how often the texture repeats across each face. Get a
texture with [`sprite_get_texture(spr, subimg)`](../reference/game-graphics.md#sprite_get_texture)
or [`background_get_texture(back)`](../reference/game-graphics.md#background_get_texture),
or pass -1 for none (the current draw colour is used). Repeats above 1 need
[`texture_set_repeat(true)`](../reference/game-graphics.md#texture_set_repeat).

```gml
// Draw event of obj_wall_block: a 32x32 cube where the instance stands
var tex;
tex = background_get_texture(bg_bricks);
d3d_draw_block(x, y, 0, x + 32, y + 32, 32, tex, 1, 1);
```

Textures work best with sizes that are powers of two (32, 64, 128, …). Other sizes are
padded up to the next power of two, and texture coordinates refer to the padded image;
[`texture_get_width()`](../reference/game-graphics.md#texture_get_width) and
[`texture_get_height()`](../reference/game-graphics.md#texture_get_height) tell which part
holds the picture.

## Primitives

For anything else, build shapes from vertices:
[`d3d_primitive_begin(kind)`](../reference/3d-graphics.md#d3d_primitive_begin) (or
`d3d_primitive_begin_texture(kind, tex)`), then `d3d_vertex…` calls, then
[`d3d_primitive_end()`](../reference/3d-graphics.md#d3d_primitive_end). The kinds are
`pr_pointlist`, `pr_linelist`, `pr_linestrip`, `pr_trianglelist`, `pr_trianglestrip` and
`pr_trianglefan`. Vertex functions with `_color` set a colour per vertex, `_texture` adds
texture coordinates (0 to 1 across the texture), and `_normal` adds a normal for
lighting.

With [`d3d_set_culling(true)`](../reference/3d-graphics.md#d3d_set_culling), triangles seen
from behind aren't drawn — the front is the side from which the vertices appear
clockwise on screen. The built-in shapes are made so that their outside faces are fronts.
In Instance culling applies to 3D primitives, shapes and models; things drawn with the
2D functions are never culled.

## Transformations

Normally coordinates are used as given. A **transformation** moves, rotates or scales
everything drawn afterwards — useful for drawing the same model in many places or
turning it to face a direction.

```gml
// Draw event: draw the ship model turned to its direction
d3d_transform_set_identity();
d3d_transform_add_rotation_z(direction);
d3d_transform_add_translation(x, y, 16);
d3d_model_draw(global.ship_model, 0, 0, 0, global.ship_tex);
d3d_transform_set_identity();
```

- `d3d_transform_set_*` replaces the transformation; `d3d_transform_add_*` applies a new
  one **after** the existing ones. Rotations and scaling are around the origin (0, 0, 0),
  so rotate first and translate afterwards, as above.
- A positive angle around z turns counter-clockwise as seen from above, matching
  `direction` and `image_angle`.
- The transformation stays in effect — also for later instances and frames, and for 2D
  drawing — until you change it. Reset it to identity when you're done.
- [`d3d_transform_stack_push()`](../reference/3d-graphics.md#d3d_transform_stack_push) and
  [`d3d_transform_stack_pop()`](../reference/3d-graphics.md#d3d_transform_stack_pop) save
  and restore the current transformation (up to 32 deep).

## Fog and lighting

[`d3d_set_fog(enable, color, start, end)`](../reference/3d-graphics.md#d3d_set_fog) blends
everything into the fog colour between the distances `start` and `end` — an easy way to
hide the far edge of the world.

Lighting is off by default. With
[`d3d_set_lighting(true)`](../reference/3d-graphics.md#d3d_set_lighting), surfaces are lit by:

- an ambient light, [`d3d_light_define_ambient(col)`](../reference/3d-graphics.md#d3d_light_define_ambient)
  (black unless you set it);
- directional lights,
  [`d3d_light_define_direction(ind, dx, dy, dz, col)`](../reference/3d-graphics.md#d3d_light_define_direction);
- point lights,
  [`d3d_light_define_point(ind, x, y, z, range, col)`](../reference/3d-graphics.md#d3d_light_define_point),
  whose light fades out over `range`.

Define a light and switch it on with
[`d3d_light_enable(ind, true)`](../reference/3d-graphics.md#d3d_light_enable); up to eight
lights shine at once. Lighting needs normals: the built-in shapes have them, and
vertices made with the `_normal` functions do. Everything else — including sprites and
text — only receives the ambient light, so with lighting on and a black ambient it
turns black. [`d3d_set_shading(false)`](../reference/3d-graphics.md#d3d_set_shading)
gives flat-shaded faces instead of smooth ones.

## Models

A model records primitives and shapes once and draws them with a single call — much
faster than rebuilding the same geometry every frame.

```gml
// Create event of a controller
global.tree = d3d_model_create();
d3d_model_cylinder(global.tree, -4, -4, 0, 4, 4, 24, 1, 1, false, 12);
d3d_model_cone(global.tree, -16, -16, 16, 16, 16, 64, 1, 1, true, 12);
```

```gml
// Draw event of obj_tree
d3d_model_draw(global.tree, x, y, 0, -1);
```

[`d3d_model_draw(ind, x, y, z, texid)`](../reference/3d-graphics.md#d3d_model_draw) draws
the model shifted by (x, y, z), with one texture for the whole model. Models can be
saved and loaded with [`d3d_model_save()`](../reference/3d-graphics.md#d3d_model_save) and
[`d3d_model_load()`](../reference/3d-graphics.md#d3d_model_load), and freed with
[`d3d_model_destroy()`](../reference/3d-graphics.md#d3d_model_destroy).

## Tips

- Draw see-through things (sprites with transparent parts, alpha below 1) after the solid
  scenery behind them. Transparent pixels still hide what is drawn later behind them.
- Things at exactly the same distance flicker against each other; keep surfaces apart.
- Very large far-clipping distances reduce depth precision. Keep the world reasonably
  sized.
